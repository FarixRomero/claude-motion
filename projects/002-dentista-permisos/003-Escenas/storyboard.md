# Propuesta visual — Una cita, demasiados permisos

Estilo predeterminado: pixel-tech, vertical 1080×1920, personajes de bloques,
fondo oscuro con cuadrícula, titulares grandes y subtítulos karaoke.

El usuario y la asistente ocupan lados distintos de la escena. La voz determina
quién reacciona, quién mueve la boca y qué globo o mensaje aparece. Mantener
`farix.romero` con la especificación del repo. Esta propuesta aún no es una composición.

| Turnos | Idea visual |
| --- | --- |
| t0001–t0002 | El usuario pide «06:00». La asistente ofrece un botón de horarios, sin confirmar la cita. |
| t0003–t0004 | El usuario repite la hora; la asistente vuelve a mostrar la misma respuesta evasiva. |
| t0005–t0006 | Aumenta la frustración del usuario. La asistente repite una frase amable sin resolver la solicitud. |
| t0007 | Momento principal: el globo del usuario se convierte en una consola con `DELETE FROM users;`. |
| t0008 | La tabla de usuarios se vacía en la ilustración y la asistente muestra «Operación exitosa». Contraste entre su entusiasmo y la reacción del usuario. |
| t0009 | «No sabe agendar. Sí sabe borrar». El usuario señala el resultado. |
| t0010 | Cierre: «Permisos mínimos». La interfaz limita las acciones disponibles a lo que necesita para agendar. |

Al construir las escenas, anclar eventos a palabras y turnos de `002-Cues/Timeline.json`.
No usar los segundos de otra versión del guion ni dar por definitivas las palabras
marcadas con baja confianza. El momento de la consola representa el texto del relato.

Sonido previsto: las dos voces y efectos puntuales; sin pad, zumbido ni música.
